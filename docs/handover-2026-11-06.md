## 9. 配布名の固定（2026-11-05、ユーザー決定）

版番号を揃えた結果、成果物名が `HY-HARNESS-0.4.0-portable.exe` になった。しかし自己更新は**動いている exe を同じパスで置き換える**方式なので、ファイル名に版を入れると「名前は 0.1.0 のまま中身は 0.4.0」という食い違いが起きる（第 6 章の混乱の一因）。そこで **B 案（固定名）** を採用し、名前を `HY-HARNESS.exe` にした。

| 変更 | 内容 |
|---|---|
| `electron-builder.yml` | `artifactName: HY-HARNESS.${ext}`（版を名前に含めない） |
| `scripts/tag-next-artifact.mjs` | ステージ名を `HY-HARNESS-next-<timestamp>.exe` に（版を含めない）。最新 3 件だけ残す |
| `scripts/check-portable-lock.mjs` | ロックのメッセージを `release/HY-HARNESS.exe` に |
| `packages/desktop/src/main.ts` | ステージ候補の案内を `HY-HARNESS.next.exe` に |
| `README.md` / `docs/implementation_status.md` / `docs/migration.md` | 成果物名・更新候補の説明を固定名に更新 |

- **変わらないもの**: 自己更新の仕組み（scheduled task → 旧 exe を `.bak-<timestamp>.exe` に退避 → 同じパスへコピー → SHA-256 検証 → 失敗時ロールバック）、ステージ候補の探索場所、署名フィード。
- **版の在り処**: サイドバー（`Desktop · v0.4.0`）、`GET /api/bootstrap`、`hy update check` の比較、署名フィードの `version`。ファイル名は版を持たない。
- **既存ユーザー**: すでに `HY-HARNESS-0.1.0-portable.exe` など旧名で置いている場合、そのファイルを「更新を適用」で置き換えれば中身は新しくなる（名前は旧名のまま）。固定名に揃えたい場合は新しい `release\HY-HARNESS.exe` に移行する（ショートカットの向き先を変える）。
