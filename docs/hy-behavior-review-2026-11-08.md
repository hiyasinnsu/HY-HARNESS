# HYの実行ログに基づく挙動レビューと修正

対象は `bench/results/2026-11-08-vision-confirm-10` のHY全10回。同じOpenCode経由の `deepseek-v4.1-flash`、effort `max` による書類分類・金額抽出で、最終的には全回が7チェックに合格している。本レビューは合否だけでは見えない、途中の失敗・誤解・手戻りを調べたもの。

各回の生成思考、実際の呼び出し、ツール結果と実装を照合した。以下の「#N / step / line」は、各 `runs.jsonl` の `logFile` が指す `session.v1.jsonl` の位置。思考上の発言だけで原因を断定せず、失敗出力や後続操作でも確認した。

## 修正した不備

### 1. Pythonの標準出力がCP932になり、文書内容を表示できない【優先度高】

- **実例:** 10回すべてで `UnicodeEncodeError`。たとえば#1 step 3 / line 25、#4 step 5 / line 35、#9 step 3 / line 25。PDF自体は正常に読めているが、`ß` や `ö` の出力で止まった。
- **モデルへの影響:** PDF抽出のやり直し、`PYTHONIOENCODING` の設定、UTF-8ファイルへの書き出しと読み直しが発生。#9では代替スクリプトの作成・実行・テキスト読み取りに3要求を使った。
- **原因:** 実行デーモンの `build_env` は環境変数を絞るが、パイプ出力するPythonの文字コードを定めていなかった。PowerShellの表示設定だけではPythonの標準出力は直らない。
- **修正:** [server.rs](../crates/hy-exec-server/src/server.rs)で子プロセスの `PYTHONIOENCODING` を既定 `utf-8` にした。利用者が明示的に受け渡す値は優先し、環境変数全体の無条件継承はしない。ファイル読み書きの既定エンコーディングは変更していない。
- **検証:** 実際のPythonが `ßö漢` を出力する結合テストを、一回限りの実行と永続シェルの両方で実施。明示指定 `ascii:backslashreplace` が優先されるケースも成功。

### 2. `document_preview` が「モデル自身が内容を見られるツール」に見える

- **実例:** #5 step 8 / line 65でPDFを視覚確認しようと呼び出したが、結果は `ok: true` とPDFのメタデータ・パスだけだった。画像は添付されておらず、その後にPythonでページを画像化して `read_image` を呼び直している。
- **原因:** 説明の「Preview a PDF」と成功フラグだけでは、プレビューの準備とモデルへの内容添付を区別できなかった。
- **修正:** [session-app.ts](../packages/hy-cli/src/session-app.ts)の説明を「メタデータとパスだけを返す」と明示し、結果にも `contentAttached: false` を追加した。モデル自身の確認にはテキスト抽出か、ページの画像化と `read_image` が必要だと案内する。
- **検証:** GUI/API経由の模擬モデルから実ツールを呼び、PDFの成功応答に `contentAttached: false` が含まれることを確認。

### 3. 引数の配置違いを直すための情報が足りない

- **実例:** #1 step 12 / line 88、step 13 / line 93で `present` を2回失敗。`files` を `args` の中ではなく `tool` と同じ階層に置き、返答は `args.files is required` だけだった。ファイル作成は成功したが、成果物提示は成功しなかった。
- **原因:** 呼び出しを誤ったのはモデルだが、ハーネスが必要な引数構造を返さず、同じ失敗からの復帰を助けていなかった。既存の具体的な案内は `shell` 専用だった。
- **修正:** [tools.ts](../packages/core/src/tools.ts)で、他のツールにも期待する入力型と「JSON形式では引数を `args` 内へ置く」という案内を返す。入力検証は維持し、誤った引数を黙って実行する変更はしていない。
- **検証:** プラグインの単体テストと `present` の結合テストで、構造を含むエラーが返ること、続く正しい入力なら成果物提示が成功することを確認。

### 4. ベンチマークで準備したGitの信頼設定がHYの実行環境で消える

- **実例:** #4 step 13 / line 87の `git status` / `git log` / `git ls-files` がすべて `detected dubious ownership` で失敗した。モデルはGitを使う確認を断念した。
- **原因:** 比較ランナーは所有者情報のないF:向けにGitの設定用環境変数を用意する一方、HYの実行デーモンは許可された変数だけを継承する。その間の受け渡しが欠けていた。
- **修正:** [run.mjs](../bench/harness/run.mjs)が作る比較専用設定で、既存の利用者指定を保ちながら `GIT_CONFIG_COUNT`、`GIT_CONFIG_KEY_0`、`GIT_CONFIG_VALUE_0` を明示受け渡しする。通常の利用者設定やグローバルGit設定は変更しない。
- **検証:** ランナーを0回実行する設定テストで、3変数と既存の受け渡し指定が残り、個人のMCP等は引き続き除外されることを確認。

### 5. PowerShellの返り値に装飾が残り、混在する表の列が消える

- **実例:** #4 step 3 / line 25の構文エラーは `_x001B_[31;1m` などを大量に含んだ。#9 step 39 / line 222では、最初の件数表に続けたファイル一覧が `1` の列だけになり、step 40で名前一覧を取り直した。
- **原因:** ハーネスのCLIXML整形は一部の改行しか復号せず、通常出力のANSI装飾も残していた。列の消失自体はPowerShellの異なる型の自動表整形によるもので、返された文字列から消えた列を復元することはできない。
- **修正:** [tools.ts](../packages/core/src/tools.ts)でCLIXMLの文字エスケープを復号し、標準出力・標準エラーの端末装飾を標準ライブラリで除去する。通常モードの[tool-registry.ts](../packages/core/src/tool-registry.ts)と詳細モードの[tool-docs.ts](../packages/core/src/tool-docs.ts)の両方に、混在する表は個別に `Format-Table`、または `ConvertTo-Json` を使う案内を追加。#4で起きたBashのheredoc構文による失敗も、Pythonファイル経由の案内で避けやすくした。
- **検証:** 色付き出力、CLIXML内の色指定、エスケープされた文字列を二重復号しないこと、終了コードと本文が保持されることを単体テストで確認。表と構文の案内の効果には、モデル側の指示追従が必要。

## 説明で軽減する改善点

### 6. 画像を読む前に縮小画像を作り、切り抜き直しを繰り返す

- **実例:** #5 step 5と#9 step 8で、上限内の元画像から独自の縮小プレビューを作成。#9 step 21〜29では表示上の位置と元画像の位置を取り違え、同じ帳票の切り抜きを3回作り直した。#9は42要求・46ツールで完了した。
- **原因の確度:** HYの画像送信が壊れていた証拠はない。メタデータは実ファイルの寸法を返している。モデルの解像度・トークン量への不安と座標の推測による手戻りであり、ハーネス側の案内不足は改善できるが、全手戻りをハーネスのバグとは断定しない。
- **修正:** `read_image` の説明を、まず元画像を直接読み、必要な細部が読めない場合にだけ切り抜く方針へ変更。座標は推定した表示ピクセルではなく元画像の寸法を基準にするよう明示。画像加工の依存や新しいツールは追加していない。
- **検証の限界:** 説明の改善であり、将来のすべてのモデルが縮小・切り抜きの手戻りを避けることは保証しない。

## ハーネスの不備と判定しなかったもの

- #2が自作スクリプトで「全ファイル」を「請求書だけの集合」と比較した失敗は、モデルが生成した検証コードの誤り。ツールは正しいエラーを返し、モデルも修正した。
- 注文書と請求書の区別や、`Total` と `Amount Due` の照合に迷って追加確認したこと自体は、課題に必要な判断。確認を一律に減らす変更はしていない。
- #8の約12.6分の大半はAPI応答待ちであり、今回の文字コード修正でその時間全体が短縮すると主張する根拠はない。
- キャッシュ命中率の変動について、確認した応答では集計の取りこぼしはなかった。今回、集計方式や結果の除外条件は変更していない。
